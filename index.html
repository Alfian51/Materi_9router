Mengapa workflow AI Coding perlu diatur?

Saat coding dengan bantuan AI, ada tiga hal yang perlu dipahami dulu: token, rate limit, dan ketergantungan pada satu provider.

Token

Token adalah satuan yang digunakan model AI untuk memproses input dan output. Semakin panjang atau kompleks interaksi yang diberikan, penggunaan token dapat semakin besar.

Rate limit

Rate limit adalah batas penggunaan yang diberikan suatu layanan AI dalam periode tertentu. Batas tersebut dapat berkaitan dengan jumlah request atau jumlah token yang dapat diproses.

Ketika batas penggunaan tercapai, request dapat ditolak sampai batas tersebut tersedia kembali.

CONTOH

Rate Limit Exceeded

Kamu minta Antigravity buatkan Navbar portofolio. Di tengah jalan muncul error ini → AI berhenti merespons → kerja kepotong sampai batas tersedia kembali.

Intinya

Ketika kita hanya bergantung pada satu provider, keterbatasan seperti rate limit dapat mengganggu proses coding. Karena itu, kita dapat menggunakan workflow yang lebih fleksibel dengan mengatur beberapa provider melalui satu gateway.

02 / 9ROUTER

Apa itu 9Router?

9Router adalah aplikasi yang dijalankan secara lokal di komputer dan berfungsi sebagai gateway / perantara antara aplikasi yang mengirim request dengan provider AI yang telah dikonfigurasi.

  • Berjalan sebagai local server di port default 20128 → http://localhost:20128
  • Dijalankan lewat CMD
  • Punya dashboard Web UI yang dibuka lewat browser
  • Menyimpan log request untuk melihat aktivitas yang masuk

Kenapa menggunakan 9Router?

Sederhananya: biar pengaturan AI rapi dan gampang dipantau dari satu tempat.

Pengaturan terpusat

Provider dan model dapat dikelola dari satu tempat.

Provider alternatif

Kita dapat menyiapkan provider lain ketika provider utama mengalami keterbatasan atau error.

Routing

Request dapat diteruskan berdasarkan konfigurasi yang dibuat.

Monitoring

Aktivitas request dapat dilihat melalui log yang tersedia.

Fleksibilitas model

Provider dan model dapat dikonfigurasi sesuai kebutuhan.

Tanpa vs dengan 9Router

KondisiTanpa 9RouterDengan 9Router
Pengaturan providerDapat dilakukan secara terpisahDapat dikelola melalui satu gateway
Pilihan providerBergantung pada konfigurasi aplikasiDapat mengatur beberapa provider

Pengaturan modelBergantung pada aplikasi / providerDapat dikonfigurasi melalui gateway

Fungsi 9Router

🚦 Routing

Meneruskan request ke provider sesuai konfigurasi.

🔄 Failover

Jika fitur failover dikonfigurasi, request dapat dialihkan ke provider alternatif ketika provider utama mengalami masalah.

🧩 Combo & Model

Menggabungkan provider dan model menjadi konfigurasi yang dapat dipilih.

🔑 API Key

Mengelola kredensial provider yang digunakan dalam konfigurasi.

📊 Log & Monitoring

Melihat request dan status aktivitas yang diterima server.

🖥️ Dashboard

Mengatur provider, model, API Key, dan konfigurasi melalui Web UI.

MITM Server merupakan server perantara yang digunakan dalam konfigurasi 9Router untuk menangani request dari aplikasi yang terhubung. Jika status di dashboard masih Stopped, klik Start Server sampai jadi Running agar konfigurasi yang membutuhkannya dapat digunakan.

Cara kerja 9Router

Alurnya sederhana: prompt dikirim, diatur, diproses, lalu hasilnya kembali.

  1. Prompt — pengguna memberikan prompt melalui Antigravity.
  2. Request — Antigravity mengirim request melalui endpoint yang telah dikonfigurasi.
  3. 9Router — menerima request dan memprosesnya berdasarkan konfigurasi provider / model.
  4. Provider — request diteruskan ke provider yang dipilih.
  5. Model AI — memproses prompt dan menghasilkan response.
  6. Response — dikembalikan melalui jalur yang sama menuju Antigravity.
  7. Hasil — Antigravity menampilkan hasil kepada pengguna.

03 / OPENCODE

Apa itu OpenCode?

OpenCode adalah salah satu provider / layanan yang menyediakan akses ke model AI melalui API.

Layanan ini berbasis website dan berbeda dengan 9Router. Kalau 9Router dijalankan lokal lewat CMD, OpenCode cukup diakses lewat browser — tidak perlu di-install.

OpenCode adalah provider AI yang SUDAH TERMASUK dalam 9Router. Tidak perlu download, install, atau setup tambahan.

Definisi

Provider

Layanan yang menyediakan model AI.

OpenCode

Salah satu provider yang sudah built-in di 9Router.

Kenapa dipakai dalam materi ini

  • ✓ Gratis (OpenCode Free dengan model-model gratis)
  • ✓ Multiple models (banyak pilihan AI yang berbeda)
  • ✓ Built-in di 9Router (sudah termasuk, tinggal pakai)
  • ✓ Tidak perlu membuat akun
  • ✓ Tidak perlu API Key OpenCode
  • ✓ Ready-to-use (sudah siap tanpa setup)

Apa & kenapa dipakai

Layanannya

OpenCode tersedia di opencode.ai. Di dashboardnya kita bisa melihat daftar provider dan model yang didukung. Dalam training ini, OpenCode kita manfaatkan sebagai provider yang nantinya dihubungkan ke 9Router.

Alasan dipakai

OpenCode digunakan sebagai salah satu provider yang dapat dihubungkan ke 9Router, sehingga request dari workflow AI Coding dapat diarahkan ke layanan tersebut sesuai konfigurasi. Ketersediaan model mengikuti layanan dan konfigurasi yang digunakan — tidak semua model selalu ada.

Provider, Model, API Key — bedanya apa?

Provider adalah sumber / layanan AI-nya. Model adalah otak AI yang memproses prompt-nya. API Key adalah kredensial / kunci akses yang dipakai untuk mengautentikasi koneksi ke layanan tertentu. Sederhananya: API Key = kunci akses.

Provider vs Model

Bagian ini wajib dipahami agar tidak ketukar. Banyak yang mengira OpenCode = Claude Sonnet — padahal keduanya punya peran berbeda.

Provider

Layanan yang menyediakan akses ke model AI.

Contoh: OpenCode
Model

Model AI yang memproses request.

Contoh: Claude Sonnet
✅ Benar: Provider → OpenCode · Model → Claude Sonnet  |  ❌ Salah: OpenCode = Claude Sonnet

Katakanlah OpenCode itu seperti penyedia listrik, dan Claude Sonnet itu seperti lampu yang kita colok. Listriknya dari OpenCode, yang menyala adalah modelnya.

"No Authentication Required" — apa artinya?

Saat connect OpenCode di 9Router, akan terlihat tulisan status "No authentication required" (warna hijau).

Artinya:

  • ✅ OpenCode sudah ready pakai tanpa setup
  • ✅ Tidak perlu login ke opencode.ai
  • ✅ Tidak perlu membuat API Key OpenCode
  • ✅ Tidak perlu authorization/approve apapun
  • ✅ Langsung bisa select model dan digunakan

Dibandingkan provider lain yang butuh:

  • ❌ Login
  • ❌ API Key
  • ❌ Authorization

STEP 01

Install Node.js

Tujuan

Pada langkah ini kita akan memasang Node.js yang dibutuhkan untuk menjalankan 9Router. 9Router dibangun di atas Node.js, jadi tanpa Node.js, command 9router tidak akan dikenali.

Langkah

  1. Buka nodejs.org.
  2. Pilih versi LTS (Long Term Support).
  3. Download installer Windows — filenya biasanya node-v20.x.x.msi.
  4. Jalankan installer → klik Next beberapa kali → pilih I Accept untuk terms & conditions.
  5. Pastikan opsi Add to PATH tercentang sebelum klik Install.
  6. Tunggu proses instalasi selesai (sekitar 5–10 menit).
  7. Setelah selesai, buka CMD / Terminal baru (jangan pakai terminal lama).

Cek instalasi

Terminal
node -v
Terminal
npm -v

Hasil

✓ Jika muncul versi, misal v20.11.0 dan 10.2.3, berarti instalasi berhasil. Jika belum muncul, tutup terminal lalu buka lagi atau restart laptop.

STEP 06

Buat Combo (Konfigurasi Provider + Multiple Models)

Tujuan

Menggabungkan provider OpenCode dengan MULTIPLE MODELS dalam satu konfigurasi yang dapat digunakan di Antigravity.

Kenapa Harus Buat Combo?

Saat menggunakan hanya 1 model, jika model tersebut mencapai rate limit, request akan ditolak dan pekerjaan terhenti. Dengan combo yang berisi multiple models, jika 1 model limit, sistem secara otomatis akan switch ke model lain. Pekerjaan tetap berjalan tanpa perlu menunggu.

Manfaat Combo dengan Multiple Models

1️⃣ Redundancy (Backup System)

Jika 1 model limit, otomatis switch ke model lain. Request tidak pernah ditolak. Pekerjaan tidak terganggu.

2️⃣ Flexibility (Fleksibilitas)

Mudah ganti/tambah/kurangi model dari dashboard. Tidak perlu restart Antigravity. Konfigurasi bisa diubah kapan saja.

3️⃣ Load Balancing (Distribusi Beban)

Request terdistribusi ke beberapa model (Round Robin). Tidak ada 1 model yang overload. Response lebih konsisten dan cepat.

4️⃣ Strategy Options (Berbagai Pilihan Routing)

Round Robin: rotate ke model berbeda setiap request. Fallback: try model utama, jika gagal coba backup. Pilih sesuai kebutuhan.

Langkah-Langkah

Langkah 1: Masuk ke Menu Combo & Vision Adapter

  1. Buka dashboard 9Router: http://localhost:20128
  2. Di sidebar kiri, klik Combo & Vision Adapter.
  3. Klik tombol + Create Combo (orange, pojok kanan).

    • ✓ oc/mimo-v2.5-free (BACKUP 1)
    • ✓ oc/nemotron-3-ultra-free (BACKUP 2)
  • Strategy: Round Robin (untuk praktik)
⚠️ PENTING: Jangan hanya pilih 1 model! Minimal 3 untuk redundancy yang baik.

Langkah 3: Klik Create

Setelah semua field terisi, klik tombol Create.

Langkah 4: Verifikasi

Troubleshooting

Masalah 1: Response Timeout / AI tidak merespons

→ Kemungkinan: Server 9Router Stopped.

Solusi:

  1. Cek status di dashboard 9Router.
  2. Lihat status MITM Server.
  3. Jika Stopped, klik Start Server.
  4. Tunggu 10 detik, coba prompt lagi.
Masalah 2: "Connection Refused" Error

→ Kemungkinan: 9Router tidak jalan.

Solusi:

  1. Periksa jendela CMD tempat menjalankan 9router.
  2. Pastikan masih running (tidak error).

09 / DEPLOYMENT

Publish Website

Vercel digunakan untuk mempublikasikan website sehingga dapat diakses melalui internet. Tahap ini dilakukan setelah project selesai dan sudah ada di GitHub.

Apa itu Vercel?

Vercel adalah platform cloud hosting yang digunakan untuk mempublikasikan website agar bisa diakses dari internet. Tanpa Vercel, website hanya bisa diakses di komputer lokal. Dengan Vercel, website bisa diakses oleh siapa saja dari mana saja melalui URL publik.

Kenapa pakai Vercel?

1️⃣ Free & Mudah

Gratis untuk project sederhana (seperti portfolio). Tidak perlu konfigurasi rumit. Sign up hanya butuh akun GitHub.

2️⃣ Auto Deploy dari GitHub

Setiap push code ke GitHub, Vercel otomatis deploy. Tidak perlu upload file manual. Update website hanya perlu git push.

3️⃣ Auto HTTPS & Custom Domain

Website otomatis secure (HTTPS). URL publik: https://portfolio-nama.vercel.app. Bisa pakai custom domain jika mau.

4️⃣ Performance Optimized

Website loading cepat. Server distributed globally. Cocok untuk production.

Troubleshooting Deployment

Jika Deployment Gagal ❌ — cocokkan pesan error dengan daftar di bawah:

Error 1: 'Failed to build'

Penyebab: Syntax error di HTML/CSS.

Solusi:

  1. Buka error log di Vercel (scroll ke atas).
  2. Cari baris yang error (misal 'unexpected token').
  3. Fix di editor lokal.
  4. Git commit & push.
  5. Vercel otomatis redeploy.
Error 2: '404 Not Found' atau Website blank

Penyebab: File index.html tidak di root folder.

Solusi: cek struktur folder → index.html HARUS di root:

Struktur folder
portfolio-nama/
└—— index.html < HARUS DI SINI
└—— style.css
└—— assets/
└—— ...
  1. Jika index.html di subfolder, pindahkan ke root.
  2. Git push.
  3. Vercel redeploy.
Error 3: Image/CSS tidak muncul (200 OK tapi blank)

Penyebab: Path file salah di HTML.

Solusi:

  1. Jangan pakai absolute path: ❌ C:/Users/.../img.png
  2. Gunakan relative path: ✓ ./assets/img.png
  3. Fix di HTML.
  4. Git push.
  5. Vercel redeploy.
Error 4: 'Build takes too long' atau timeout

Penyebab: File terlalu besar atau process timeout.

Solusi:

  1. Optimize image size (compress).
  2. Hapus file yang tidak perlu.
  3. Reduce CSS/JS size.
  4. Git push ulang.
Error 5: Cannot authorize GitHub

Penyebab: Belum authorize akses.

Solusi:

  1. Buka GitHub Settings → Apps & integrations.
  2. Cari 'Vercel'.
  3. Klik untuk authorize.
  4. Kembali ke Vercel, refresh page.
  5. Coba import repository lagi.
